# sdfmodeler — 階層SDFモデラー (sqm .ssq 対応)

MagicaCSG 風の階層的 SDF モデル (プリミティブ + smooth-union/subtract +
translate/rotate/mirror の関節階層) をブラウザ上でリアルタイム編集し、
[sqm](../sqm) でそのままレンダリングできる `.ssq` を読み書きするモデリングツール。
`scenes/frog.ssq` のようなモデルの新規作成・編集ができる。

## 起動

ES modules を使うため http サーバ経由で開く (`index.html` 直接ダブルクリックでは動かない):

- **macOS**: `serve.command` をダブルクリック (初回に警告が出たら右クリック→「開く」)。
  ターミナル派は `./serve.sh`
- **Windows**: `serve.bat` をダブルクリック
- 手動起動:

```bash
cd sdfmodeler
python3 -m http.server 8642
# → http://localhost:8642
```

## 操作

- **ビューポート**: ドラッグ=回転 / Shift+ドラッグ or 右ドラッグ=パン / ホイール=ズーム /
  **クリック=パーツ選択** (GPUピック。ミラー越しでも元ノードを選択)
- **ギズモ** (表示オプションで ON/OFF、モードは **W=移動 / E=回転 / R=スケール** かセレクタ):
  - **移動**: ワールド軸固定の XYZ 矢印 (軸移動) + 3枚の平面ハンドル (2軸平面移動) +
    中央円 (ビュー平面移動)。**Shift ドラッグ=0.1 グリッドスナップ**。
    回転祖先 (`rotate` チェーン) の下でもワールド空間でまっすぐ動く (逆回転をローカル
    デルタに掛ける。数学: `js/anchor.js`)。center を持たないグループは自動で
    `translate` ラップして移動 (矢印キー移動と同じ規則)
  - **回転**: ワールド軸まわりの3リング (奥半分は減光=前後の深度キュー)。
    **Shift ドラッグ=15° スナップ**。選択が rotate (または親が rotate) なら
    **その pivot にリングが出て deg を合成** (関節をそのまま曲げられる。既存の
    回転成分は保持)。無ければ自身のアンカーを pivot にした `rotate` を自動ラップ。
    合成は S_new=R(ワールド軸をローカル化, φ)·S_old → Euler 逆分解 (rotate-mat は m0..m8 へ直接)。
    **中央の白ドット=pivot をビュー平面ドラッグで移動** (Shift=0.1 スナップ。関節の
    「曲がる位置」決め。deg≠0 だと pivot 移動で子の見た目も動くので、関節の仕込みは
    deg=0 のうちに。rotate が無いパーツでは自動ラップ=見た目不変で関節だけ仕込める)
  - **sweep 制御点** (移動モード): 掃引チューブ選択中は各経路点に**緑ドット**が出て、
    ビュー平面ドラッグで個別に動かせる (Shift=0.1 スナップ。ギズモ本体=全点平行移動とは別)。
    回転祖先の下でも正しくローカル化 (pivot ドットと同じ数学)
  - **スケール** (リーフ限定): 軸ハンドル (四角チップ) + 中央四角=一様。
    **Shift=×0.1 刻みスナップ**。軸はリーフの**ローカル軸** (回転していれば追従)、
    a/b 端点系 (カプセル等) は**部品軸=長さの伸縮 (中点固定)・垂直=radius**。
    球/八面体は一様のみ。一様は右/上ドラッグ=拡大・左/下=縮小 (±140px で ×2/×0.5)。
    寸法マッピングは `js/scale.js` (torus: 横=major/縦=minor、cylinder: 横=radius/縦=height、
    cone: 横=tanθ 変換/一様=height のみ、box-frame: thick は一様時のみ 等)。
    sweep は**経路点を重心まわりに拡縮** (一様=半径も s 倍 / 軸=その成分のみ伸縮=形を潰す/伸ばす)
- **ツリー (左)**: ノード選択。緑=プリミティブ, 青=CSG演算, 黄=変換。
  **行をドラッグ→別の行へドロップ**でその直後 (同じ階層) に移動
  (オブジェクト行へのドロップはルート直下末尾へ。別オブジェクトへの移動も可)。
  **オブジェクト行をドラッグ→別オブジェクトへドロップで2オブジェクトを統合**
  (ツリーを移して元オブジェクトは削除。surface は統合先のものが適用)
- **インスペクタ (右)**: 数値は直接入力のほか **「↔」グリップを左右ドラッグ**で
  スライダ編集 (Shift で微調整)。子/兄弟の追加、translate/rotate/mirror/smooth-union
  等での**ラップ**、アンラップ、複製 (DUP)、並べ替え、削除 (DEL)。
  **兄弟/子の追加は参照パーツの隣 (+x) に、参照に比例した寸法で配置**される
  (旧: ローカル原点固定で既存ジオメトリに埋まり「追加したのに見えない」となっていた。
  空オブジェクトの最初のパーツは前のオブジェクトの隣に出る)
- **表示オプション (ビューポート右上)**: 品質 / 影 / **AO** / 床 / 軸 / 色分け /
  **深度**(距離の白黒マップ, 近=白遠=黒) と **📷 PNG**(現在の表示をそのまま画像保存)
- **影 / AO のチェックは「シェーダ生成時」のフラグ** — この2つだけは uniform で
  切っていない。HLSL は距離関数の呼び出し箇所を全てインライン展開するので、
  **実行時に切ってもコンパイル代は満額かかる**ため。切り替えると1回だけ
  再コンパイル待ちが入るが、プログラムキャッシュに両方載るので戻すのは即時。
  **どちらも既定 OFF** で、この状態が一番速い (影・AO 入りに対し 32〜47% 短縮。
  実測と経緯: docs/2026-08-24_sdfmodeler_calcNormal_4タップをループに畳む.md)。
  ⚠ **AO OFF は接地部・付け根の陰りが浅くなる** — 形の見え方を詰めるときは ON に
- **コンパイル中はビューポート上部にバッジが出る** (「シェーダをコンパイル中… N 秒経過」)。
  シェーダの再構築は数秒〜十数秒かかることがあり、出さないと固まったように見えるため。
  ⚠ ステータス行の「コンパイル中…」は**メッシュ再生成の完了メッセージに上書きされる**
  ので当てにしない (バッジの方が確実)
- **操作中の自動軽量化**: カメラ/ギズモのドラッグ中は**影と AO をスキップ**し、
  解像度も実フレーム時間から**自動調整** (30ms 超で下げ、余裕があれば戻す。0.12〜0.6×)。
  離した瞬間にフル画質で再描画されるので、ノード数が増えても操作は軽いまま
- **フォーカスシェーディング** (リーフ40超で自動): ギズモドラッグ中、**編集パーツ+
  隣接の土台ボーンだけを実体でレイマーチ**し、残りは骨格 (ドット/線) で文脈表示。
  非フォーカスのリーフは距離関数呼び出しを省く (union に中立な d=1e9) ので、
  SDF が数百個でもドラッグが軽い (レイマーチ対象が数個に減る)。離すとフル復帰。
  ドラッグ開始時に1回だけシェーダを再コンパイル (layout 不変で params は流用)
- **ボーン (スケルトン) 表示**: 表示オプション「ボーン」で骨格をオーバーレイ
  (a/b 端点系リーフ=白い線分+端点、center 系=点、rotate 関節の pivot=アンバーのリング)。
  ポーズ編集時の関節視認に便利。さらに **ON 中のドラッグはレイマーチを完全に停止**して
  ボーンだけ追従 (実測 ~0.5ms/フレーム) — どれだけ重いモデルでも視点操作が軽い。
  離すとフル画質へ。**ON にすると影も自動 OFF** (静止時レンダも軽く。OFF で元の設定に
  復帰、ボーン中に手動で影を入れ直した場合はその選択を尊重)。
  ※ mirror の鏡像側ボーンは表示されない (恒等近似)
- **表示セレクタ (SDF / メッシュ)** (2026-07-20): ツールバーの「表示」セレクタで
  ビューポートの描画方式を選ぶ。**既定は「メッシュ 標準」= 起動時からメッシュ表示**
  (重いモデルの俯瞰・配置用。色や造形を正確に見たいときは「SDF (レイマーチ)」へ)。
  - **SDF (レイマーチ)**: 本物の SDF レイマーチ。色/影/色分け/深度が出るが、レイマーチが
    GPU ハング級の重量モデル (leaf.ssq 201ノード等) では重い。軽いモデル向き
  - **メッシュ 粗/標準/高/最高**: sqm 本体の場ダンプ→marching cubes をラスタライズ
    (serve.py の `/__mesh__` = `SQM_SDF_DUMP` + tools/field2obj.py。要 serve.py + ../dist/sqm)。
    **描画コストが三角形数のみに依存 = 重量モデルでもカメラ/配置編集が滑らか**。
    数値は polygonize グリッド解像度 (100/160/240/320。細部と再メッシュ時間をトレード。
    leaf: 標準=0.3秒/55k tris, 最高=1.6秒/239k tris)。編集は約0.4秒デバウンスで自動再メッシュ化。
    単色プロキシ (パーツ色/影/融合面の色は出ない)。
    **2026-08-04 に2段高速化**: ①エンジン側 = 場ダンプの粗→細疎評価 (表面が無いと
    証明できたブロックをスキップ。メッシュはバイト一致・chawan 2.6倍) ②UI側 =
    **オブジェクト単位の内容ハッシュキャッシュ** (編集で変わったオブジェクトだけ
    再メッシュ化しクライアントで結合。招き猫16obj: 初回160ms→編集後18ms)。
    per-object の grid はシーン寸法比でスケールしボクセル寸法を全体ダンプと揃える。
    実装 js/meshcache.js (純関数, test/meshcache.mjs) + serve.py は無改修
  - **serve.py 無し/失敗時は自動で SDF にフォールバック** (メインが真っ白にならない)。
    選択は localStorage に永続 (重量モデルはリロード後もメッシュで開き、初回レイマーチの
    ハングを回避)。WebGL コンテキストロストからの自動復旧つき (GL資源を再生成しメッシュを再アップロード)
  - ※クリック選択 (GPUピック) は1pxレイマーチのまま — 重量モデルでは初回クリックだけ
    シェーダの GPU コンパイルで数秒〜数十秒待つことがある
- **材質色**: インスペクタの**「色」**で任意ノードに実レンダ色を設定 (未設定=親から継承、
  既定=オブジェクト色)。融合面では色が距離比でなじむ。オブジェクト統合ドロップ時は
  元の色が自動で付与され**統合しても色が残る**。.ssq へは `(mcolor (c r g b) <sub>)`
  ラップとして書き出され、**sqm 本レンダでも融合したまま色が混ざる** (要 2026-07-10 以降の sqm)。
  .json 保存も無損失。**💉スポイト**で選択パーツの色をコピー、**ペースト**で別パーツへ適用
  (コピー色はボタンのスウォッチに表示、リロード後も保持)
- **Ctrl+Z / Ctrl+Shift+Z**: undo/redo。**Delete**: 選択ノード削除
- 編集内容は localStorage に自動保存
- **新規シーンは空の滑らか和ルート**から開始。原点に軸クロス (X=赤/Y=緑/Z=青,
  ツールバー「軸」で切替)、ビューポート中央のクイック追加から最初のパーツを配置

## ファイル

- **書き出し .ssq** — そのまま `sqm -i model.ssq -o out.png ...` でレンダリング可能。
  カメラ位置は現在のビュー、surface/light は raw テキストとして保持・編集できる
- **🎬 sqm テストレンダ** (ビューポート上部) — 現在のカメラのまま serve.py の `/__render__`
  経由で `../dist/sqm` を起動し、本レンダ PNG をモーダル表示 (Shift+クリック=高品質
  1000px AA2 ソフト影 GI)。プレビュー(単色近似)とシェーダ/影の実際の見た目の突き合わせ用。
  sqm リポジトリ内での起動が前提 (`SQM_BIN` で別パス指定可)。ローカル専用
  (任意シーンを subprocess 実行するので serve.py を公開網に出さないこと)
- **保存 .json** — エディタ専用形式 (ノード名なども保存)
- **開く** — `.ssq` / `.json` に加え、**sqm が焼いた `.png` をそのまま開ける**
  (2026-08-06)。sqm は出力 PNG の IEND 直前に iTXt チャンクでシーン本文を
  zlib 圧縮して埋めている (`dist/png_meta.cpp`) ので、**レンダリング結果の画像が
  シーンを持ち歩いている**。`.ssq` を別に管理しなくても、気に入った絵を投げ込めば
  そのモデルが開く。実装 `js/pngmeta.js` (`DecompressionStream('deflate')` を使うので
  外部ライブラリ不要)。
  ・判定は**拡張子でなく先頭8バイトのシグネチャ** — リネームされていても効く
  ・sqm 以外の PNG (メタが無い) は明示エラーで止まり、**編集中のモデルは壊れない**
  ・`SQM_PNG_META=0` で焼いた画像には入っていない
  `(rotate-mat ...)` は直交行列なら自動的に編集可能な Euler 角
  `(rotate (deg ...))` に復元される
- **サンプル**: rabbit / bear / frog / arm (関節チェーン) / **human (人体ボーン)** /
  **dog (犬リグ)** / **trex (T-REXリグ)** など。human は骨盤ルートの17関節カプセルリグ
  (背骨→胸→首→頭、肩→肘→手首、股→膝→足首)、dog は腰ルートの22関節四足リグ
  (胴→胸→首→頭+鼻先+両耳、前後4脚、尾2節)、trex は22関節の二足竜リグ
  (下顎関節=口が開く、尾3節、指行性の後脚4関節、先細り部位は round-cone-ab)。
  いずれも左=青系/右=赤系の色分け。各関節の rotate を選んで回転ギズモ (E) でポーズ付け

## 対応ノード (sqm sexp_input.cpp / sdf.cpp と同一セマンティクス)

- **プリミティブ**: sphere / box / ellipsoid / torus / plane / box-frame / capsule /
  cylinder / cylinder-ab / round-cone / round-cone-ab / capped-cone / capped-cone-ab /
  cone / octahedron / superquad /
  **lathe** (回転体: 2D輪郭(r,y)をy軸回転。壺/ゴブレット/駒/ボウル。軸半径オフセット・
  厚み>0で開シェル・種類/分割。輪郭は「✎ 輪郭を編集」で 2Dプロファイルエディタ(latheモード)を開いて
  デザイン。**エディタで線を描いて適用すると回転体パーツを新規追加**もできる。GLSL正確プレビュー) /
  **extrude** (押し出し: 2D閉輪郭(x,y)を z±半厚 へ押し出した板。額縁/銘板や、円錐だと
  尖ってしまう葉っぱ形 (猫の耳) 向き。半厚/厚み>0で開シェル/種類・分割。輪郭は
  「✎ 輪郭を編集」で 2Dプロファイルエディタ(extrudeモード)を開いてデザインし、
  適用で押し出しパーツを新規追加もできる。GLSL正確プレビュー。
  **`(round (r ..) ..)` で稜線を丸める**と「切り紙」感が消える) /
  ※ **別の SDF の表面に沿わせる (decal)** は専用ノード無しで書ける:
     `intersect( onion(t T, round(r R, <ホストと同じ形>)), <法線方向に伸ばしたカッター> )`
     — ホストの距離場を厚み 2T の殻にして、カッターの断面で輪郭を切り出す。
     距離場そのものなので**厚みが曲率に完全追従**する (平たい楕円体を置くと縁が潜り
     中心が飛び出す)。ホストが重い木なら decal 側は**近似プロキシ**でよい
     (表面が一致していれば正しく沿う)。例 `examples/decal_test.ssq`。
     ※intersect のガード球は**最小の子**で包むので枝刈りが効く (和で包むと
       decal の球がホスト全体より大きくなり無効化される)。

  **sweep** (掃引チューブ: 3D経路点列に沿って円形断面を掃く。点毎半径=テーパー、
  種類=折れ線/スプライン(Catmull-Rom)/Bスプライン、ループ(closed)、分割(steps)。
  インスペクタで点の行編集 (x y z r + ◇=次の点との中間に挿入 + ✕削除 + 末尾追加)、
  ギズモ移動は全点平行移動・移動モードの緑ドットで各点を個別ドラッグ。
  **任意断面** `(profile ..)(twist ..)` (Phase 2) も一級対応: インスペクタの「✎ 断面を編集」で
  別タブの**2Dプロファイルエディタ** (`profile.html`) が開き、断面を描いて「sdfmodeler へ適用」で
  戻すと該当 sweep に反映 (BroadcastChannel 連携。届かなければエディタ側に警告=ACK 方式)。
  **3Dプレビューは正確表示** (エンジンと同式の RMF/マイタpad/fac を JS で焼き込み GLSL 評価)。
  重い評価なので**ギズモドラッグ中だけ近似チューブ+ボーンに自動降格**し、離すと正確表示へ復帰。
  ねじり°もインスペクタで編集 (twist はエンジンと同じ9°自動細分)。
  丸錐カプセル連鎖の min = 厳密SDF。ロープ/パイプ/蔓/取っ手/角。examples/sweep_test.ssq)。
  未対応リーフは raw ノードとしてテキスト保持 (ラウンドトリップ保証、プレビューは非表示)
- **blob (native メタボール)** (2026-08-23): `(blob ..)` と `(no-blend ..)` を一級対応。
  表示は GLSL でなく **WASM (js/mbmesh.wasm = vclay 1992 評価器+Bloomenthal)** の
  再メッシュを重ね描き — 場・等値面・行列規約が sqm と厳密同一
  (ssq_edit --obj と faces バイト一致・書き出しの sqm レンダー画素一致を検証済)。
  ドラッグ中 level5 (~10ms/97blob) で追従、離すと level6。クリック選択は可視楕円体の
  CPU レイキャスト。scale は**支持半径** (可視半径 ≈0.614×scale @weight3)。
  **頂点色つき** (mcolor > object surface 色を vclay evalSurf が密度ブレンド —
  no-blend の硬い色境界も sqm と同じ)。選択 blob は可視楕円体の 3 リングで
  ハイライト。**no-blend はシーンパネルの群チップで編集** (2つ順にクリックで
  ペア切替)。**Pair** = blob インスペクタ「◇ 相手を選ぶ」で対称配置 blob の
  鏡映同時編集 (ssq_edit 移植: 軸は pos 差最大を自動判定)。ギズモ回転は
  rot を直接回す (rotate ラップを作らない)。OBJ 書き出しは blob メッシュも合流。
  **(deform amp freq phase [mode 0..3]) も一級対応** (旧記法のみ。凹凸が
  プレビュー/メッシュに実形状で出る — 式は sqm と同一で検証済み。一般形と
  (mode dsl) は raw 保全)。blob-bulk は raw 保全のまま。WASM の再ビルドは
  vclay リポジトリで `make wasm` (要 emcc。⚠ vclay_src を触ったら中で make —
  トップの lib ルールは依存を見ない)。
- **ハイブリッド表示 + SDF ローカル再メッシュ** (2026-08-23): focus ドラッグ
  (リーフ40超) 中は「編集中 object だけレイマーチ + 残りはキャッシュ済み
  メッシュの深度合成」— 編集 fps がシーン総ノード数から切り離される。
  文脈メッシュは **js/sdfmesh.wasm** (= dist の実パーサ sexp_input + sdf_eval +
  marching tetrahedra を em++ で束ねたもの, Web Worker) がローカル供給するので
  serve.py 無しでも出る (grid>112 と (grid ..) リーフ/volume はサーバ経路)。
  メッシュ表示は**頂点色つき** (surface 色 + mcolor を engine の
  sdf_mcolor_blend で評価。サーバ焼き分も colorize で後付け)。ドラッグ中は
  編集中 object だけ grid48 の per-frame ドラフトで融合が追従 (≈12fps)。
  **blob Lv セレクタ** (blob のあるシーンで表示) = blob 再メッシュの確定解像度。
  低 Lv は粗い格子が場を均す = amp>iso の deform でも破れが閉じた塊になり、
  **⬇OBJ 書き出しにも同じ解像度が使われる** — 「見えている閉じた造形を
  そのまま固定する」ためのノブ (高 Lv は真の等値面に近づき破れが出る)。
  再ビルドは dist で `make wasm-sdfmesh` / 検証は `make sdfmesh_test` (閉曲面検査)。
  詳細: docs/2026-08-23_sdfmodeler_blob統合_mbmesh_wasm.md
- **CSG**: union / intersect / subtract / smooth-union(k) / smooth-subtract(k) /
  blend(u) / invert — エディタ上は n-ary、書き出し時に元ファイルと同じ入れ子方向
  (smooth-union=右fold, subtract系=左fold) の2項に畳むため距離場が完全一致
- **変換**: translate / rotate (deg + pivot) / rotate-mat / mirror (normal + d) /
  **repeat** (count + offset = 子を offset 方向に count 個線形複製。柵=横 offset、
  階段=斜め offset、タイル=repeat のネスト。1ノードで繰り返し構造が作れ count は
  ドラッグで即変化。評価は隣接2コピーの min — 子はセル幅 |offset| に収めるのが目安) /
  **round** (r = 角丸め/膨らまし d-r) / **onion** (t = 厚み t の殻化 |d|-t。subtract で
  切ると器になる) / **elongate** (h = 各軸 ±h 引き伸ばし。球→カプセル等。子は原点周りに定義) /
  **twist** (rate °/unit = y軸ねじり) / **bend** (rate °/unit = x軸曲げ)。
  twist/bend は非 Lipschitz なので子の大きさから安全係数を自動計算して距離を縮める
  (歪みが強いほどマーチが遅くなる)

## 実装メモ

- プレビューは WebGL2 の単一フラグメントシェーダにツリーを直接コード生成して
  sphere tracing (距離関数・smooth CSG・回転規約は sdf.cpp と同式)
- 数値パラメータは全て `uniform float uPar[]` に載せるため、**値の編集では
  再コンパイル不要** (ドラッグ中も滑らか)。構造変更時のみ再生成
- 選択ハイライトとクリックピックは計測付き probe 関数を同時生成
  (uniform 分岐なのでノード追加でシェーダが増えない)

## 運用とトラブルシューティング

### プレビュー(WebGL)とレンダ(sqm)は別経路 — ズレたら「どちらが古いか」を疑う
ビューポートの 3D は **ブラウザの WebGL シェーダ**、🎬/⚙ のレンダは **別プロセスの sqm バイナリ**で
描いています。両者は別のコードなので、**片方だけ古いと見た目がズレます**。実際にあった例:
プレビューは触角付き(最新 JS)なのにレンダは丸いブロブ(古い sqm が `(profile …)` を理解できず
`(radius 1)` を巨大な円筒として描画)。ズレを見たら、まず「JS が古いのか、sqm が古いのか」で切り分ける。

### レンダ用 sqm バイナリの解決順と SQM_BIN
serve.py の `/__render__` が使う sqm は次の順で決まる:
1. 環境変数 **`SQM_BIN`**(あれば最優先)
2. 無ければ **配信フォルダの隣 `../dist/sqm`**

**Desktop 配布コピー等は `../dist/sqm` が古い/無いことがある**ため、同梱の `serve.sh` /
`serve.command` は「SQM_BIN 未設定なら(存在すれば)sqm リポジトリの `dist/sqm` を既定に使う」よう
設定済み(`[ -x ]` ガード付きなので別環境では自動スキップ)。起動時に `レンダ用 sqm: …` と表示される。
- **エンジン(C)を更新したら**: `cd dist && make` で `dist/sqm` を再ビルド。SQM_BIN 運用なら
  レンダ側は**自動で最新**を使う(JS の同期とは別物 — JS だけ配ってもレンダ用バイナリは更新されない)。
- 別マシン/別配置で使うなら起動前に `SQM_BIN=/path/to/sqm ./serve.sh` を指定。
- **serve.py を変更したらサーバ再起動が必要**(Python はホットリロードしない)。

### 「変更が反映されない」= 配信元(ポート/オリジン)を疑う
- `Cache-Control: no-store`(serve.py)なので通常はリロードで最新になるが、**開きっぱなしのタブは
  JS モジュールがメモリに残る** → 反映されないときは **ハードリロード**(⌘⇧R)。
- **どのポートがどのフォルダを配信しているか**を必ず確認する。過去に「8642 が Desktop の旧コピー、
  8643 がプロジェクト」で混乱した。配信元は `lsof -a -p <pid> -d cwd` で分かる。
- **別タブ連携(プロファイルエディタ / レンダ設定)は same-origin 必須**。sdfmodeler と別タブが
  違うポートだと BroadcastChannel が届かない → エディタ側に「受信していません」警告(ACK)が出る。
  必ず同じ URL(同じポート)で開くこと。
